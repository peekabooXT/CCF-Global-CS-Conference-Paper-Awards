# v1.0：本地管理与服务器公开发布

## 分工

| 功能 | 本地管理版 | 服务器公开版 |
| --- | --- | --- |
| 论文检索、会议年度颁奖 | 保留 | 保留，只读且仅展示已核验数据 |
| 来源收录管理 | 保留独立入口 | 不设独立入口，来源信息合并到论文详情 |
| 采集与导入、记录核验、采集覆盖 | 保留 | 不部署，相关接口返回 404 |
| LLM 连接、运行日志、Token 用量、保存网址 | 保留在本机 | 不部署、不上传 |
| 审核与发布按钮、发布历史 | 保留 | 不部署 |

服务器不是隐藏菜单的管理版，而是独立的 `public_api.py` 和公开前端构建。发布包只包含公开查询代码、已核验数据和公开静态页面，不包含 `api.py`、LLM、采集、导入、审核或覆盖模块。SQLite 使用只读连接，服务账户不能修改公开数据库。

论文详情按需读取关联来源：保留官网获奖页面，同时展示 JeffHuang 等聚合收录的原始题名、作者及单位、条目编号、来源网址、核验状态及去重关联。聚合收录与官方授奖证据区分展示，不补造奖项原名、不新增重复论文或获奖事件。取消公开导航入口不删除来源表或关联数据；本地仍可独立检查来源与去重结果。

## 日常使用

1. 本机运行 `run_all.py`，打开本地管理版。
2. 本地采集、导入、查看日志，核对原始来源。新数据默认待核验。
3. 点击右上角 **审核与发布到服务器 / GitHub**。
4. 预览待审核数量和证据问题；填写审核人、说明，勾选已人工核对的确认框。
5. 点击 **一键审核并更新服务器和 AWARDS.md**。页面每两秒读取发布进度。

系统的自动校验只能判断字段与证据结构是否有效，不能替代人工核对事实。确认后，当前预览中的全部有效待审核记录转为已核验；已排除数据不发布。仅有已核验数据、没有新增待核验数据时，也可以再次发布。

发布内容是本机全部已核验数据的完整快照，而不是追加。因此删除或排除本地记录后再次发布，会从服务器公开数据中移除相应记录；本机数据为空时另需明确确认空数据发布。

## 同步与时间

一次发布使用同一个 Asia/Shanghai 时间与版本号：

- GitHub：`AWARDS.md`、`docs/awards/BY_CATEGORY.md`、`BY_YEAR.md`、`BY_AWARD.md`。
- 可复现数据：`data/exports/public-data.json`、`publication.json`，以及兼容旧导入器的 `verified-records.json`。
- 服务器：同一份已核验快照、公开页面顶部的最近发布时间、发布版本号和 GitHub 提交号。
- 本地：SQLite 发布历史记录开始时间、完成时间、审核人、审核数量及两端结果；每次发布的文件留在 `data/publications/<版本号>/`。

两端成功后会尝试将当前本地 Git 分支快进到发布提交，从而更新本地 `AWARDS.md`。若本地索引有未提交修改、当前分支不匹配或无法快进，则保留你的修改并在发布历史提示；生成后的完整文件仍保存在 `data/publications`，不进行强制覆盖。

标准论文、获奖事件中的论文、JeffHuang 等来源收录都进入统一索引；原始奖项名称不改写。来源只证明聚合收录、未提供原始奖项名时，标注“来源未提供奖项原名”，不伪造官方奖名。

GitHub Actions 已改为只读一致性验证，不再定时采集、重建或推送数据。

## 首次配置与安全

本地忽略文件 `data/local-publish-config.json` 保存仓库、分支、服务器地址、受限发布账户和本机 SSH 密钥路径，不保存私钥正文、root 密码或 API Key。

```json
{
  "repository": "peekabooXT/Global-CS-Paper-Awards-Agent",
  "branch": "main",
  "server_host": "47.107.172.42",
  "server_user": "awardsdeploy",
  "server_key": "C:/Users/XuTao/.ssh/global_cs_awards_deploy_ed25519"
}
```

GitHub 使用本机 Git 凭据管理器的现有登录，在临时独立检出中提交数据，不把浏览器中的 API Key 用作发布凭证，也不强制覆盖主分支。服务器使用独立 SSH 密钥；该密钥只允许 `check` 和校验过的公开发布包，不允许终端登录、端口转发或任意命令。服务器接收程序须由 root 所有，发布账户仅获准重启指定公开服务。

本地管理接口限制为本机连接和本机 Host/Origin，不对外部署。请不要将本地管理端口公开映射到互联网。

代码更改后，先在 `frontend` 运行：

```powershell
npm run build
npm run build:public
```

`run_all.py` 会在公开构建缺失或前端源文件更新时自动准备公开构建。仅更新数据无需重新构建前端。迁移到另一台电脑时，要重新配置 Git 登录、发布密钥和 SSH 已知主机信息；不要将私钥上传 GitHub。

## 失败、重试与备份

预览数据发生变化时会拒绝旧确认，须刷新预览。连接预检失败不会进行批量审核；已完成的审核结论不会因网络失败丢失。

GitHub 和服务器不能组成跨系统事务：先更新 GitHub，再上传服务器。若后一阶段失败，发布历史明确显示“GitHub 已更新，服务器失败”，不会误报两端完成。核对原因后可以再次点击发布；再次发布使用新的版本和时间，不重复创建论文。

服务器先验证压缩包路径、数据库完整性及核验状态，再原子切换版本并重启。启动检查失败会恢复上一版。以前的公开版本保留在服务器 `releases`；本地原始数据库、管理日志和迁移备份不包含在公开包中。

服务器旧管理数据通过备份转移到本机。`scripts/import_management_backup.py` 可将管理数据库迁入本地；保留现有本地论文和覆盖结论，保存迁移前备份，重复执行不会重复导入日志。
